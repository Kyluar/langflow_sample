Manual do Desenvolvedor - CTD

Este documento tem a intenção de familiarizá-lo com o ambiente e ferramentas utilizadas pelo time de desenvolvimento da CTD. Daremos uma  breve descrição de cada ferramenta e como utilizá-la no seu dia à dia.

Editor de código (VS Code)
O que é um Editor de Código?
Diferente de um editor de texto comum (como o Bloco de Notas ou o Word), um Editor de Código é uma ferramenta projetada especificamente para escrever software.
O editor de código foca em:
Destaque de Sintaxe (Syntax Highlighting): Colorir o código para que você identifique funções, variáveis e erros visualmente.
Auto-completar: Sugerir comandos enquanto você digita.
Indentação Automática: Manter o código organizado e legível.
Diferença para uma IDE
Um editor de código é focado primariamente na edição de arquivos de texto. Ele é leve, abre instantaneamente e é altamente personalizável. Diferente de uma IDE, que é um pacote completo de ferramentas projetado para um ecossistema específico.
Vantagens do VS Code
O VS Code, desenvolvido pela Microsoft, domina o mercado por oferecer um equilíbrio perfeito entre performance e funcionalidades.
Extensibilidade infinita: existem milhares de extensões gratuitas que permitem que o editor suporte qualquer linguagem.
Terminal Integrado: o terminal já vem embutido com CMD e PowerShell, facilitando rodar scripts, compilar código ou gerenciar containers Docker sem tirar as mãos do teclado.
Integração com Git: você consegue ver quais linhas foram alteradas, fazer commits, criar branches e resolver conflitos de código através de uma interface visual muito intuitiva.
Remote Development:  o editor permite conexões a ambientes de desenvolvimento como, um container Docker ou um servidor Linux remoto, de forma transparente.
Leve e Gratuito: ele é totalmente gratuito e de código aberto, com uma comunidade gigantesca que resolve problemas e cria temas novos todos os dias.
Download: https://code.visualstudio.com/download
Docs: https://code.visualstudio.com/Docs
Git 
É um Sistema de Controle de Versões Distribuído (VCS) que serve basicamente para rastrear o histórico de alterações em arquivos de texto. Ele é "distribuído" porque cada desenvolvedor possui uma cópia completa do repositório (com todo o histórico) em sua própria máquina, não dependendo apenas de um servidor central para funcionar.
Qual problema ele resolve?
Antes do Git, o desenvolvimento colaborativo era um caos. Ele resolve, principalmente, três grandes dores de cabeça:
A Perda de Progresso: Sem controle de versão, se você fizesse uma alteração que quebrasse o sistema e salvasse o arquivo, era muito difícil (ou impossível) voltar exatamente ao estado anterior que funcionava.
Conflitos de Trabalho: Quando duas pessoas editavam o mesmo arquivo ao mesmo tempo, a última que salvasse acabava sobrescrevendo o trabalho da primeira.
A Bagunça Organizacional: O Git elimina a necessidade de duplicar pastas para criar backups manuais. Ele mantém tudo organizado em uma "linha do tempo" invisível e eficiente.
Vantagens de utilizar o Git no desenvolvimento
O uso do Git traz benefícios que vão desde a segurança do código até a agilidade da equipe:
Ramificações (Branching): Você pode criar "ramos" para testar novas funcionalidades ou corrigir bugs sem afetar a versão principal do código que está funcionando (a main).
Colaboração eficiente: Vários desenvolvedores podem trabalhar no mesmo projeto simultaneamente. O Git oferece ferramentas para unir essas diferentes contribuições de forma inteligente (merging).
Rastreabilidade Total: Você sabe exatamente quem alterou o quê, quando e por que (através das mensagens de commit).
Segurança e Backup: Como cada membro da equipe tem uma cópia local, as chances de perder o projeto inteiro por uma falha de servidor são quase nulas.
Velocidade: A maioria das operações do Git ocorre localmente no seu computador, o que o torna extremamente rápido em comparação com sistemas que dependem da rede para cada comando.

Download: https://git-scm.com/install/
Docs: https://git-scm.com/docs

Gerenciador de pacotes PNPM
 Para que serve um gerenciador de pacotes?
Instalar e atualizar bibliotecas externas no seu projeto.
Gerenciar dependências: Se a biblioteca A precisa da biblioteca B para funcionar, o gerenciador garante que ambas estejam presentes.
Padronizar o ambiente: Garante que todos os desenvolvedores do time usem exatamente as mesmas versões das ferramentas.
Por que utilizar PNPM ao invés do NPM?

Embora o NPM seja o padrão que vem com o Node.js, o PNPM introduziu uma arquitetura muito mais inteligente. Suas principais vantagens são:


Economia de espaço em disco: ele guarda apenas uma cópia de cada pacote em uma pasta global no seu computador. Nos seus projetos, ele cria apenas "links" (hard links) para esse arquivo central.
Velocidade Superior: como o PNPM não precisa baixar ou copiar arquivos que já existem no seu computador, ele é drasticamente mais rápido que o NPM. Além disso, o processo de instalação do PNPM é dividido em etapas que rodam em paralelo de forma mais eficiente.
Fim das dependências fantasmas: o PNPM é rigoroso: você só consegue importar no seu código aquilo que você explicitamente adicionou ao seu arquivo package.json.
Suporte nativo a monorepos: O PNPM foi desenhado com o conceito de Workspaces em mente, logo, ele tem capacidade de gerenciar um repositório com diversos projetos de forma mais fluída que o NPM.
	
Docs: https://pnpm.io/motivation

Docker
O que é o Docker?

O Docker é uma plataforma de código aberto que utiliza a tecnização de containers. Ela tem capacidade de empacotar o código da sua aplicação junto com todas as dependências (bibliotecas, configurações, runtime) em uma única unidade chamada Imagem. Quando essa imagem é executada, ela se torna um Container.
Qual problema ele resolve?

A Maldição do "Na minha máquina funciona": O desenvolvedor usa Python 3.10 no Windows, mas o servidor de produção usa Python 3.8 no Linux. Isso gerava bugs difíceis de rastrear.
Conflitos de Dependências: Instalar um projeto que precisa da biblioteca "X" na versão 1.0 e outro que precisa da versão 2.0 na mesma máquina costumava quebrar o sistema.
Demora no Onboarding: Um novo desenvolvedor levava dias configurando o banco de dados, variáveis de ambiente e servidores antes de escrever a primeira linha de código.
Vantagens para o Desenvolvedor

Isolamento Total: Você pode rodar múltiplos containers com diferentes versões de linguagens ou bancos de dados sem que um interfira no outro.
Portabilidade: "Build once, run anywhere". O mesmo container que roda no seu notebook vai rodar identicamente no servidor de testes e na nuvem (AWS, Azure, Google Cloud).
Ecossistema (Docker Hub): Você não precisa instalar o PostgreSQL ou o Redis no seu sistema. Basta baixar uma imagem oficial e rodar um comando.
Versionamento de Infraestrutura: Com o arquivo Dockerfile, a configuração do seu ambiente vira código. Isso permite que você versione a infraestrutura junto com o projeto no Git.

Docs: https://docs.docker.com/get-started/

Banco de dados POSTGRESQL com DOCKER
O'Que é o PostgreSQL?
O PostgreSQL (ou Postgres) é um sistema de gerenciamento de banco de dados relacional e open source, permite armazenar, organizar e consultar grandes volumes de dados usando a linguagem SQL.
Usando PostgreSQL via Docker
Utilizar o PostgreSQL com Docker é uma forma rápida e eficiente de rodar o banco de dados sem precisar instalar tudo manualmente no sistema. O Docker cria um container isolado, com o PostgreSQL já configurado, facilitando testes, desenvolvimento e padronização de ambientes.
Instalação via CMD:
docker pull postgres

docker run -p 5432:5432 -v /tmp/database:/var/lib/postgresql/data -e POSTGRES_PASSWORD=1234 -d postgres

Documentação: https://github.com/docker-library/docs/blob/master/postgres/README.md

Front-end Mobile com Expo Router
O que é o Expo Router?
O Expo Router é uma solução de navegação para aplicações mobile baseada em React Native e no ecossistema Expo. Ele utiliza o conceito de roteamento baseado em arquivos, onde a estrutura de pastas define automaticamente as rotas e telas da aplicação, de forma semelhante ao Next.js no ambiente web.
Essa abordagem elimina grande parte da configuração manual de navegação, tornando o código mais simples, previsível e fácil de manter.
Como o Expo Router funciona?
A pasta app/ define todas as rotas do aplicativo


Cada arquivo representa uma tela


Cada pasta representa um grupo de rotas


Arquivos especiais permitem criar layouts, stacks, tabs e fluxos de autenticação
Exemplo:
app/
 ├── index.tsx        → Tela inicial
 ├── login.tsx        → /login
 ├── dashboard/
 │    └── index.tsx   → /dashboard
 └── (auth)/
      ├── login.tsx
      └── register.tsx


Docs: https://docs.expo.dev/router/introduction/

Back-end com Nest.js
O que é o Next.js?
O Nest.js é um framework para construção de aplicações back-end em Node.js, totalmente compatível com TypeScript e inspirado em conceitos de arquitetura modular, injeção de dependências e programação orientada a objetos.
Ele combina boas práticas de frameworks consolidados (como Angular e Spring) com a flexibilidade do ecossistema Node.js, sendo ideal para APIs escaláveis e de fácil manutenção.
Arquitetura Modular
O Nest.js utiliza uma arquitetura baseada em módulos, onde cada módulo representa uma parte do domínio da aplicação.
Controller: Define as rotas e recebe as requisições HTTP
Service: Contém a lógica de negócio
Module: Agrupa e organiza os componentes
Exemplo:
users/
 ├── users.controller.ts
 ├── users.service.ts
 ├── users.module.ts

ORM Prisma

O que é um ORM (Object-Relational Mapping)
É uma técnica/ferramenta que permite que você interaja com um banco de dados relacional usando a linguagem de programação que você já domina em vez de escrever SQL puro.
Antes dos ORMs, os desenvolvedores enfrentavam alguns desafios "espinhosos":
SQL manual e erros de sintaxe: Escrever SELECT * FROM users... dentro de strings é propenso a erros que o compilador não detecta. Se você esquecer uma vírgula, o erro só aparece ao rodar o código.
Manutenção difícil: Se você mudar o nome de uma coluna no banco, precisa caçar todas as strings SQL no seu projeto para atualizar.
Inconsistência de dados: Transformar manualmente o resultado de uma query em um objeto que seu código entende consome tempo e gera código repetitivo (boilerplate).
Segurança: ORMs ajudam a prevenir nativamente ataques de SQL Injection, tratando os dados antes de enviá-los ao banco.
Por que utilizar o Prisma ORM?
O Prisma é uma ORM focada na experiência do desenvolvedor (DX). Aqui estão os principais diferenciais:
Tipagem estática com TypeScript: o Prisma gera automaticamente tipos TypeScript baseados no seu esquema de banco de dados. Isso significa que você tem o acesso total ao recurso de autocompletar do seu editor.
O Arquivo schema.prisma: Em vez de definir modelos em classes complexas, você define tudo em um arquivo de configuração legível e centralizado.
Migrations Simplificadas: o Prisma Migrate lê seu arquivo de esquema e cria automaticamente os arquivos SQL necessários para atualizar seu banco de dados, mantendo um histórico claro de todas as mudanças.
Script Seed: é um script que você executa para inserir dados automaticamente no banco de dados. É extremamente útil para garantir que todos os desenvolvedores do time tenham o mesmo estado inicial de dados. Para semear seu db execute npx prisma db seed
Prisma Studio: ele vem com uma interface visual (GUI) embutida para você visualizar e editar seus dados sem precisar de ferramentas externas como DBeaver ou pgAdmin. É só rodar pnpm prisma studio.

Fluxo padrão de mudanças no banco de dados
Sempre que houver qualquer alteração no schema do banco, o seguinte fluxo deve ser seguido obrigatoriamente:
1️ - Criar e aplicar a migração:

Cria um novo arquivo de migração


Aplica a alteração no banco local


Mantém o histórico versionado no repositório


2-  Gerar o Prisma Client atualizado:
pnpm prisma generate

Atualiza os tipos TypeScript


Garante que o código reflita o schema atual


3 - Popular dados iniciais (seed):
pnpm prisma db seed

Insere dados essenciais para o funcionamento do sistema


Útil para desenvolvimento e testes

Biome (Formatador e Linter)

O Biome é uma ferramenta "tudo-em-um" (all-in-one) voltada para o ecossistema de desenvolvimento web, especificamente para projetos que utilizam JavaScript, TypeScript, JSON e CSS.
Para que ele serve?
A principal função do Biome é simplificar o "tooling" (conjunto de ferramentas) do seu projeto. Em vez de configurar três ou quatro bibliotecas diferentes, o Biome resolve tudo de uma vez:
Formatador (Formatter): Ele organiza o seu código automaticamente (como o Prettier), garantindo que todo o time siga o mesmo estilo de escrita. Ele é focado em ser 97% compatível com o Prettier, mas muito mais rápido.
Linter: Ele analisa o código em busca de erros lógicos, bugs em potencial ou práticas ruins (como o ESLint). Ele já vem com centenas de regras prontas para te ajudar a escrever um código mais limpo.
Organizador de Imports: Ele limpa e ordena os seus import de forma automática, removendo o que não está sendo usado.
Por que usar o Biome?
Extremamente rápido: escrito em Rust, ele é ordens de magnitude mais rápido que o ESLint ou Prettier. Em projetos grandes, a diferença de performance é nítida.
Configuração Única: Você não precisa de eslint.config.js, .prettierrc e outros arquivos espalhados. Um único arquivo biome.json controla tudo.
Sem Dependências: Ele funciona de forma independente. Você não precisa instalar 50 plugins diferentes para que o Linter entenda o TypeScript, por exemplo. Já está tudo embutido.
Docs: https://biomejs.dev/pt-br/guides/getting-started/
Conventional Commits

É uma especificação simples para adicionar metadados às mensagens de commit. Ele cria um conjunto de regras para facilitar a leitura humana e, principalmente, a automação por ferramentas de software.
A Estrutura Básica
A mensagem de commit deve ser estruturada da seguinte forma:
<tipo>[escopo opcional]: <descrição>
[corpo opcional]
[rodapé opcional]
Os Tipos Principais (type)
Embora você possa personalizar, os tipos mais comuns (baseados na convenção do Angular) são:
feat: Uma nova funcionalidade para o usuário.
fix: Correção de um bug.
docs: Alterações apenas na documentação.
style: Alterações que não afetam o sentido do código (espaço em branco, formatação, ponto e vírgula faltando, etc).
refactor: Alteração de código que não corrige um bug nem adiciona uma funcionalidade.
test: Adição de testes ausentes ou correção de testes existentes.
chore: Atualizações de tarefas de build, configurações de pacotes, etc.
Por que usar
Geração automática de CHANGELOGs: Ferramentas conseguem ler seus commits e listar exatamente o que mudou na nova versão.
Versionamento Semântico (SemVer): Determina automaticamente se a próxima versão do seu app será um Patch, Minor ou Major através de ferramentas de CI/CD.
Facilidade na Navegação e Debug: imagine que um bug surgiu na produção. Ao olhar o histórico, mensagens padronizadas ajudam você a filtrar o que importa rapidamente.

Docs: https://www.conventionalcommits.org/pt-br/v1.0.0/
Artigo: https://medium.com/linkapi-solutions/conventional-commits-pattern-3778d1a1e657
